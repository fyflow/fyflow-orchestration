# Q774 — a non-string `of` or branch entry is accepted

`spec/flow-definition.md`'s `FD-V21` refuses *a declared key [that] holds a value of the wrong type*. **For two id-typed
keys the validator holds the type only through the graph, and so accepts the wrong one** — measured by W210's conformity
reader on `ceecb90` + W210:

| the value | what the validator does |
|---|---|
| a `join` whose `of` is `null`, `5`, `[]`, `{}` or `true`, in a flow with no `fanout` or `map` | `FD-V2` and `FD-V6` each read `of` only `if (typeof of === 'string')`; no `FD-V21` clause names `of` — **zero findings** |
| a `fanout` whose `branches` mix a string with a non-string, `["b", "c", 5]` | `FD-V21` checks only that `branches` is an array; `FD-V9`'s floor and distinctness count the non-string; the graph builder drops it — **zero findings**, a fanout of the strings alone |

`edge.to` and a map's `branch` were given exactly this `FD-V21` clause, for the stated reason that the graph builder
drops a non-string before `FD-V2` can see it (`validate.ts`' comments at both). `of` and a branch entry were not.

**Why it was not fixed in W210**: the fix is two clauses, but it REFUSES documents 0.10.0 accepts — a change in what a
consumer's flow does — and W210's row moved no verdict. `definitionSchema()` follows the validator meanwhile
([ADR 0132](../decisions/0132-a-definitions-shape-is-a-schema-built-from-the-validator.md) rule 2): it holds `of` and a
branch entry to the id charset only where they are strings, and W210's suite pins both documents as accepted by both.

**Resolved by W215 under P44 (d1), decision 2** — the first of the two closing conditions: `FD-V21` refuses a join's `of`
that is present and not a string and each `fanout` branch entry that is not a string (one finding per entry, by index),
`spec/flow-definition.md` v0.52; `definitionSchema()`, static and registry forms, holds both to the id charset
unconditionally, and W210's two ACCEPTS pins became refusals. **A change in what is accepted** — BREAKING, 0.12.0: both
documents in the table above are refused, each by `FD-V21` alone. Cases:
`spec/examples/invalid/FD-V21--join-of-is-not-a-string.flow.json` and `FD-V21--fanout-branch-entry-is-not-a-string.flow.json`.
