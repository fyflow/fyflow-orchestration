**Measured at P47's declaration, not assumed.** Every `needs` value is a REFERENCE: `"."`, `"$payload"`,
`"$item"`, a node id, its array form, a `?` suffix and `!error` (`spec/flow-definition.md` section 3, the
`needs` table). There is no literal form, so a loop whose seed is its own `needs` (P47 decision 4) can only
seed from what the run already holds.

**Without it**, a node of the built-in transforming type before the loop shapes the seed - one dispatch per
RUN, not per round, so the cost is small. **With it**, the grammar gains a form that is not a reference,
which every reader of `needs` - `referenceTarget`, `FD-V26`-`FD-V29`, the wiring check, `inputOf` - would
have to tell apart from one.
