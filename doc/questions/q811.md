The review of the pull request carrying P47 (2026-11-15), findings 7-10. Each was read off the diff, not measured.

| | where | what |
|---|---|---|
| 7 | `src/driver/driver.ts`, `loseLoop` and `fireLoop` | both re-implement `settleJoin`'s unsatisfiable and satisfied arms: the `firedJoins` latch, `joinSettled`, `onUnsatisfiableJoin`, `JP-R10`'s `branch.lost` for the enclosing region, the reading's `offer`, the successor's `enter`. A later change to any of those is made in two places, and a loop's join diverges from every other join if one is missed |
| 8 | `src/driver/driver.ts`, `run.ended` | a round's terminal event type reaches `settleLoop` through a mutable field written in `emit` and cleared in `settleLoop`, at five call sites, where an argument through `settleJoin` would carry it. A new emit site, or an early return between the two, leaves a stale value the next settlement reads |
| 9 | `src/driver/driver.ts`, `settleLoop` | every continuing round keeps the arrival as `run.state` and clones it again for the next round, and `run.state` is read only on a break. A loop with no break `end` (`loopBreakEnds` knows statically) pays one deep copy of the carried state per round for a value nothing reads |
| 10 | `src/definition/validate.ts`, `conditionProblem`; `src/definition/wiring.ts`, `loopValueOf` | the comparison scope and the message are chosen by comparing a DISPLAY string (`'a loop'`, `'an if gate'`), so a third caller or a reworded string silently gets the gate's messages; and `loopValueOf` takes a join it never uses |

**Why not in W231.** W231 fixed what was wrong for a consumer (the review's 1, 2, 4, 5, 6); these four change no
behaviour. *(This read "7 and 8 sit in the functions W232 has to restructure" until W232 was redeclared: its first
attempt, which did restructure them, was reverted.)*

**Resolved by W233 (2026-11-15).**

| | outcome |
|---|---|
| 7 | **done** — `joinFires`, `leaveJoin` and `joinDies` are the two arms, called by `settleJoin` and by `fireLoop` / `loseLoop` |
| 8 | **done** — the terminal event's type is `settleJoin`'s fourth argument, at each of its five call sites; `LoopRun.ended` and `emit`'s clause are gone |
| 9 | **declined** — the maintainer's (a). `spec/join-policy.md` `JP-R15` requires both halves: a round's entry receives *its own copy*, and the state a round started with is *held … until the join becomes terminal*. The copy is also what keeps a round's input from aliasing a result the run retains. Measured on 2,000 rounds: one copy of the state is 9% of a round for a 3-field state and for 1 KB, 21% at 100 KB |
| 10 | **done** — `conditionProblem` takes the site (`CONDITION_SITES`), and `loopValueOf` takes no join |

encloses it (a join told `arrived` for `lost` ran three rounds and fired) — tests added there.*
