**Evaluated by P32 on 2026-10-13**, when the maintainer asked which crucial flow nodes are missing.
`FD-V10` refuses a cycle, and four things assume there is none: the task-id scheme (a node's id is
unique per branch path, [Q13](q13.md)), `reaches(X)`'s irreflexivity (section 4), `FD-V29`'s certainty
walk, and a resume's replay (`RN-R26`), which re-asks every decision over the stored settlements in
order.

**What a flow does without one:** a task's `retryPolicy` re-runs a failing task (v0.16); a `map`
iterates a list the previous task returned; a worker that must poll polls inside its own `run()`.
**What none of those covers:** a decision AFTER a task that sends the run back to an earlier node —
*validate, and on failure fix and validate again* — which is the shape to wait for.

**Resolved by [P47](../plans/p47-what-may-repeat-in-a-flow-and-how-a-round-hands-on-to-the-next.md), 2026-11-14.**
The shape asked for is not a cycle. A `loop` is a region whose ONE branch runs round after round, each round at
its own branch-path segment, so the four things above that assume no cycle are untouched by construction: the
id scheme (`ID-R6` widened, the grammar unchanged), `reaches(X)`, `FD-V29` (certain of less at a breakable
loop's join, ADR 0145 decision 7) and the replay, which regenerates every round from the stored settlements
(`spec/run-state.md` section 9, measured by W230 at every cut). *Validate, and on failure fix and validate
again* is a loop whose body validates, routes a failure through `fix`, and whose `until` reads the validation.
