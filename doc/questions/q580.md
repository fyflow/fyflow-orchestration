**What changed.** `scripts/build.mjs`'s envelope-worker plugin replaces
`new URL('./envelope-worker.ts', import.meta.url).href` in the npm bundles with a `data:` URL on
Node and a `Blob` URL in the browser (W152 Outputs (9)). So an npm consumer's browser bundle no
longer has to serve the envelope worker beside itself. A bundle of the JSR SOURCE is unchanged.

**Measured.** `npm run pack:smoke` clause **P11** loads the installed `dist/browser` in Chromium and
runs a typed node threaded and inline, serving ONLY the consumer's own `worker.js`. Both modes reach
`completed`. Probe `K5d` points the browser branch back at a file beside the bundle, and P11 turns
RED in both modes (*"the run did not settle in 20 s"*).

**The three sentences, verbatim at W152:**

1. `AGENTS.md:2653-2656`: *"A bundled worker is your asset: inside a bundle `import.meta.url` is the
   bundle's own URL ([Q261]), so `jsonata.worker` — like the envelope worker itself — has to be
   served beside your bundle as a module of its own for a pool's thread to load it."* The `jsonata.worker`
   half is still true. The *"like the envelope worker itself"* half is false for the npm dist.
2. `src/scheduler/bootstrap.ts:53-56`, on `ENVELOPE_WORKER_URL`: *"Resolved against THIS module, so
   it is the published package's own file wherever the package is installed"*. This ships in
   `dist/types/src/scheduler/bootstrap.d.ts`, where the value is a ~10 KB `data:` or `blob:` URL.
3. `spec/runtime-targets.md`, `RT-R12`'s stated limit: *"as the envelope worker already is
   ([Q261])"*. This is still true of a source bundle and false of the npm dist, so the change is a spec change.
