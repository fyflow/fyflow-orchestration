# ADR 0130 — A regenerated asked element keeps the stored run's time

**Status:** accepted — [P43](../plans/p43-what-a-flow-and-a-run-say-as-data-rather-than-as-prose.md) stop-and-ask (e),
answered (e1) by the maintainer 2026-10-23 as recommended, decision 7, facts 6 and 7; written by
[W208](../work-items/w208-a-transforms-cause-and-when-an-ask-was-asked.md). It defines `spec/run-state.md` v0.35's
clauses of `RN-R37`, `RN-R36` and `RN-R19`. It amends no ADR: [ADR 0065](0065-a-resume-replays-the-stored-stimuli-refuses-what-it-cannot-regenerate-and-re-dispatches-what-was-in-flight.md)'s
prefix check and [ADR 0109](0109-an-ask-parks-with-nothing-dispatched-and-its-answer-is-its-result.md)'s park are
unmoved, and `CHECKPOINT_FORMAT` stays `1`.

## Context

fyflow-app's *pass 4* #4 asked WHEN an ask was asked — the time a host shows beside a person's open question and
measures a wait from. Every outcome record carries `observedAt`, the driver's injected `now` (`OR-R3`); the `asked`
element carried none (P43 fact 6). Adding one is a field; the constraint is the REPLAY. An `asked` element is
REGENERATED by a resume, never fed (`RN-R19`), and `append` compares it with the stored element by `sameData`, every own
key (`RN-R20`). **A regenerated element stamped with a fresh `now()` would differ from the stored one at its first ask,
so every resume of a run with an ask — and every `inputOf` reading (`RN-R45`, ADR 0128), which replays through the same
`append` — would be refused `diverged` there.** Leaving the time out of the comparison ((e2)) would resume, but the
resumed run would carry the REPLAY's time, so a wait measured across a resume would restart at every resume.

## Decision

**An `asked` element carries `observedAt`, the driver's injected `now` where the branch entered the ask; a replay that
regenerates it within the stored prefix takes the stored element's time.**

1. **A live ask, and an ask past the stored tail** (`RN-R24`), is stamped `now()` — the clock an outcome record settled on
   the same step reads.
2. **Within the stored prefix** the regenerated element takes the `observedAt` of the stored element at its own position
   where that element is an `asked` carrying a NUMBER there, and carries NONE otherwise. So a checkpoint written before
   0.11.0 — no `observedAt` — resumes and compares equal (`sameData` reads an absent key and an `undefined` one alike), and
   its resumed run carries no time for that ask. A stored `observedAt` that is not a number is not one a driver wrote: the
   regenerated element, carrying none, differs from it and the resume is refused `diverged` at that element. Every other
   element at that position is refused exactly as before.
3. **The rule lives in `ask()`, the one writer**, so `resume()` and an `inputOf` reading inherit it through the one replay;
   nothing is excluded from `sameData`.
4. **The fold surfaces it** as `NodeRun.askedAt` on the ask's entry — present only where the element carried one, and
   KEPT through the answer as `input` is (`RN-R36`). Both fields are OPTIONAL and additive.
5. **`CHECKPOINT_FORMAT` does not move** (`RN-R16`: it moves when what a checkpoint CARRIES moves as a format; an added
   optional key on an existing kind is not one — as `attempted`, `paused` and `asked` itself were added at format 1).

## Consequences

1. **A resume and a reading show when the person was ASKED, not when the replay ran** — measured by W208's L2 suite from
   every stored prefix of a map of asks under a later clock: each element within the prefix carried its stored time
   (hand-edited to 501, 502, 503, each its own), each past the tail the later clock, and `inputOf` was never `diverged`.
2. **The OTHER direction is a refusal this ADR does not add but does cause** (P43 fact 7), MEASURED by W208 on
   `ask-after-a-task.flow.json` (the session scratchpad's `w208/older.ts`): a checkpoint written by this driver, its
   `asked` element carrying `observedAt: 200`, resumed by the driver at `e52348d` (0.10.0) is **refused `diverged` at
   position 2**, the `asked` element — that driver regenerates no time. The 0.10.0 checkpoint resumes on this driver,
   carrying none, and on its own. This is the same consequence every element kind added since format 1 (`interrupted`,
   `paused`, `asked`, `attempted`) has for a driver that predates it: **a run is resumed by a driver at least as new as the
   one that wrote it.**
3. **A consumer comparing a whole `asked` element or ask entry with a literal now sees one more key** — W208 measured six
   such comparisons in `examples/l6.ts`'s W182 block and set the time aside there; a consumer switching on the element's
   kind, or reading `input`, is unaffected.
4. **What this forbids**: stamping a regenerated element with `now()` "because the replay is now", and excluding
   `observedAt` from `sameData` — the first refuses every resume, the second ((e2)) loses the stored time.
